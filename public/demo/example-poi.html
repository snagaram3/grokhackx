01 · The data

Hugging Face travel places

Dataset audiala/audiala-places — landmarks with lat/lon already stamped. HawkxAI streams the Hub CSV when it finishes in time, else uses a vendored sample.

Fields we keep name · city · country · lat/lon · category · Wikidata URL · sitelinks
Live refresh hub = streamed CSV · sample = local slice · ~96 places max
On the map violet pins — separate from live receipts so they never merge

Never invents a place from a title. Coords come from the dataset only.

03 · Pipeline

What the code does

Collect Stream Hub CSV or load sample · stamp lineage
→
Pair Haversine ≤ 400 km · hop pin ids for the map
→
Call Industry buckets · outlook · hourly window
  • Category → industry (museum→entertainment, temple→hospitality, tower→real-estate…)
  • Hover a pair row → both pins light + dashed hop (bowed when co-located)
  • Place filter floats nearby POIs (e.g. Tokyo keeps Kyoto bright within 450 km)
  • Hourly liveNear persists in Cloud SQL so cold starts keep the window

04 · Outcomes

What operators see

Pairs table POI · industry · live source · km — evidence of proximity
Industry cards outlook thin / stable / rising / peaking · variables & constraints from overlap only
Headline + next action e.g. weather on entertainment · hazard near hospitality → Safety unmet
Stay thin when thin < 2 pairs → no invented industry call · need a second hour for next-window

Measured overlap only — never a story about why the place “matters.”
